## 1. Project Limitations

1. **Single-User, Offline Desktop Architecture (Scope & Concurrency):**
   - *Limitation:* PIEMS is strictly a single-user, single-process, offline desktop application (Decision D-01, NFR-05). It does not provide network synchronization, remote database connections, multi-user role-based access control, or concurrent file locking if multiple operating system processes open `piems.db` simultaneously.
   - *Evidence:* [`pom.xml`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/pom.xml) and 77 production Java files contain zero network imports (`java.net.*`, `javax.net.*`), verified by `PackageDependencyTest.checkPackagesForbidsNetworkImports` (`TC-NFR05-02`); [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-01; `audit/2026-11-15-campaign/final-report.md` §6.3.

2. **Budget Alert Hysteresis State is Not Persisted (Decision D-46):**
   - *Limitation:* Budget threshold alerting state (`lastNotifiedStatus`) is session-scoped and ephemeral in-memory inside `BudgetMonitor`. The SQLite `budgets` table stores only category limits and months (Decision D-46). When the application restarts, `FinanceService.preloadBudgets` resets `lastNotifiedStatus` to `OK`. Consequently, if spending remains over the 80% warning or 100% exceeded threshold across an application restart, the alert repeats upon the next transaction or budget status evaluation in the new session.
   - *Evidence:* [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-46; verified by `BudgetRestartAlertTest.alertRepeatsAfterRestartWhenSpendingRemainsOverThreshold` (`TC-FR10-16`).

3. **Service Reachability & SQLite Persistence for Recurring Rules and Savings Goals (FR-11, FR-12, FR-18, Decision D-47):**
   - *Limitation:* Domain entities, schedule calculations, date clamping (`Schedule`, `RecurringGenerator`), and savings goal progress lifecycle (`SavingsGoal`, `GoalContribution`) are fully implemented and verified by unit and black-box tests. However, they lack `FinanceService` facade methods, persistence repositories (`RecurringRuleRepository`, `GoalRepository`), and UI screens. Consequently, recurring rules and savings goals cannot be created, manipulated, or persisted across restarts through the user interface or facade. Under FR-18, accounts, categories, transactions, and budgets persist across restart (D-46); goals and recurring rules are not persisted because they cannot yet be created through the service.
   - *Evidence:* [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-47; [`docs/SRS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/SRS.md) §3.1 (FR-11, FR-12, FR-18 marked Partially verified); [`docs/COVERAGE.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/COVERAGE.md) §7 Item 3.

4. **Savings Goal Lifecycle Restricted to Active and Achieved States (Question Q-008, Decision D-35):**
   - *Limitation:* In v1.0, `SavingsGoal` supports only `ACTIVE` and `ACHIEVED` lifecycle states. Additional states specified in preliminary project requirements (`OVERDUE`, `CANCELLED`) were formally deferred to post-v1.0 iterations to prevent scope creep.
   - *Evidence:* [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-35; `SavingsGoal.java`; verified by `StateTransitionBlackBoxTest.goalTransitionsFromActiveToAchievedWhenTargetReached` (`TC-FR12-06`).

5. **Large Facade Class (`FinanceService.java`):**
   - *Limitation:* `FinanceService.java` contains **1,128 lines of code** (measured via `(Get-Content src/main/java/piems/service/FinanceService.java).Count`). While individual methods strictly adhere to the 30-line limit enforced by Checkstyle, the class acts as a single unified facade coordinating accounts, transactions, transfers, categories, budgets, reports, exporters, and CSV import. Future iterations would benefit from decomposing this facade into smaller domain coordinators (e.g., `BudgetService`, `TransactionService`, `ReportService`).
   - *Evidence:* `FinanceService.java` line count command; [`checkstyle.xml`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/checkstyle.xml) (0 violations).

6. **Deferred Database Backup, Physical Restore, and Schema Migration (FR-20, NFR-10):**
   - *Limitation:* Automated file backup (`BackupService`), physical file restore, and pre-migration backup snapshots are deferred (Could requirements, not implemented in v1.0). In SQLite, schema alterations across versions (such as D-46 adding the `idx_budget_cat_month` unique index) do not have an automated migration runner; older development databases must be manually deleted or re-seeded.
   - *Evidence:* `audit/test-results.md` Scenario S6 notes; [`docs/COVERAGE.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/COVERAGE.md) §7 Item 1; [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-43, D-46; `audit/2026-11-15-campaign/final-report.md` §6.1.

7. **Single Currency with Configurable Default Constant (Decision D-24, D-31):**
   - *Limitation:* The default application currency is Indian Rupee (`INR`, `₹`) configured as a constant `Money.DEFAULT_CURRENCY` with exactly 2 decimal places (minor units = paise). Multi-currency transactions, currency conversion, live exchange rates, and denominations with 3 decimal subunits are not supported. Furthermore, `Money` is strictly non-negative; negative balances are prohibited, and credit card liabilities are tracked as a separate non-negative variable `outstandingDebt` on `CreditCardAccount`.
   - *Evidence:* [`Money.java`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/src/main/java/piems/domain/Money.java#L18); [`CreditCardAccount.java`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/src/main/java/piems/domain/CreditCardAccount.java#L15); [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-24, D-31; `RequirementAcceptanceBlackBoxTest.fr07NetWorthDerivedAcrossMixedAccountTypes` (`TC-FR07-04`).

8. **Prohibited Overdraft on Bank Accounts (Decision D-27):**
   - *Limitation:* Bank accounts strictly prohibit overdrafts in v1.0; expenses or debits exceeding the derived account balance are rejected with `InsufficientFundsException`. Only credit cards support borrowing up to a configured credit limit.
   - *Evidence:* `BankAccount.java`; `BankAccountTest.bankRejectsExpenseAboveBalanceWhenNoOverdraft` (`TC-FR03-04`); [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-27.

9. **No Run on a Second Operating System Observed (NFR-06):**
   - *Limitation:* Local testing and verification have been executed exclusively on Windows 11 with JDK 17 (`pom.xml` target 17, running under Oracle JDK 25.0.1 runtime). While a multi-OS CI matrix (`windows-latest`, `ubuntu-latest`, `macos-latest`) is configured in `.github/workflows/ci.yml`, no green GitHub Actions run has been observed or confirmed from this offline environment.
   - *Evidence:* `.\mvnw.cmd -v` reports `OS name: "windows 11", version: "10.0", arch: "amd64"`; `.github/workflows/ci.yml`; [`docs/COVERAGE.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/COVERAGE.md) §4 (NFR-06 marked Partially verified); execution on macOS and Linux **[needs evidence]**.

10. **Human User Acceptance Trial Pending (NFR-04):**
    - *Limitation:* While automated script verification confirmed that adding an expense requires $\le 4$ inputs (`ConsoleScriptTest.recordsExpenseInFourInputs`, `MainPresenterTest`, `TC-NFR04-01`), the formal human participant acceptance trial (`audit/acceptance-checklist.md`) is documented but remains pending participant execution.
    - *Evidence:* `audit/acceptance-checklist.md`; [`docs/COVERAGE.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/COVERAGE.md) §4 (NFR-04: "automated input-count test passes; user trial pending"); human trial completion **[needs evidence]**.

11. **Automated Bytecode-Level Mutation Testing (NFR-07):**
    - *Limitation:* Automated PITest mutation coverage across all 77 production classes was constrained by JVM runtime bytecode version 69 compatibility (Oracle JDK 25 runtime running Maven, despite `--release 17` in `pom.xml`). Mutation coverage was verified manually across five key domain mutants in Step 6.2.
    - *Evidence:* `pom.xml` (`<maven.compiler.release>17</maven.compiler.release>`); `.\mvnw.cmd -v` (`Java version: 25.0.1`, bytecode version 69); `audit/2026-11-15-campaign/final-report.md` §6.2.

12. **GUI Visual Styling and Component Rendering:**
    - *Limitation:* Swing GUI testing is conducted headlessly via `MainPresenter` (Decision D-40) asserting model states, event routing, and table row updates. Visual component rendering, font scaling, and OS theme fidelity are not automated.
    - *Evidence:* [`docs/TEST_PLAN.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/TEST_PLAN.md) §3 ("GUI pixel layout not tested"); [`docs/DECISIONS.md`](file:///c:/Users/muank/Desktop/Sem%203/SE/PROJECT%20SE/docs/DECISIONS.md) D-40.
